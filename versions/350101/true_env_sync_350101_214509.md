## Remaining gap

The true-device log records 32 `getrandom(16)` events, but Unidbg currently uses deterministic PRNG-by-seed, not exact per-call replay. If X-Medusa still diverges after pid/tid/time/rootfs sync, the next step is to add a `metasec.fixedGetrandomHexSequence` replay path and feed these recorded true-device random blocks back into `UnixSyscallHandler.getrandom()`.
