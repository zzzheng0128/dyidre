## 重要更正（2026-09-05 晚）

1. **`0x1000000e` 必须返回 Long，不是 Integer**：lib 在拿到返回值后立即
   `FindClass(java/lang/Long)` + `longValue()` 拆箱。返回 Integer 会触发 JNI 异常，
   init 链在 `0x1000022` 前中断，且 VMP 会走异常 fallback 长路径
   （exeVMInner=7、F5/F7、vmCode 0x201800/0x1f6670）——**该长路径是异常分支，
   不是真机路径**。真机 init 链完整（含 0x1000022 ×4），对应短路径。
2. **`.msf3` KV 值会在真机上轮换**：`sdi`/`de9ecbee…`/`ptmr`/`ftm` 的真机当前值
   与 8-31 rootfs 快照不同（`cb_value` 和静态 key 不变）。rootfs 已更新为
   2026-09-05 真机值。值轮换不改变路径形状，只改变 X-Medusa pack 内容。
3. 相位1 unidbg 与真机的差距实际只剩：`0x1000009`（时区）、`0x100000a`（语言）、
   `0x10000006`（CPU JSON）、`0x100002c`、心跳相位——unidbg req01 未触发。

## 对"彻底还原"的含义

1. 相位1 缺口（17 个 op）大概率是 unidbg 初始化路径被简化——补法：对齐 init 序列或接受差异。
2. 相位2 是 X-Medusa/X-Soter env 字段的真正来源——要做值级保真，需要让 unidbg
   触发这段（多次签名或显式调用采集入口），再用 props 注入真机值。
3. 相位3 心跳与签名算法无关，但在线 session 保活需要——还原"长在线客户端"时才做。
4. 所有 op 值注入通道已就绪：`-Dmetasec.msB.<op>.<key>=<值>`，无需改代码。
